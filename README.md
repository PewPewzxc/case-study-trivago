# trivago Rate Connect onboarding email

This is my case study for the Email Development & Marketing Automation internship: a responsive HTML email built from your Figma file, tested in Outlook, Gmail and Apple Mail on my own devices, plus an AMPscript version for Salesforce Marketing Cloud.

I'd start with [WRITEUP.md](WRITEUP.md). It's short: how I approached it, how I made decisions, what broke, and how I used AI. [NOTES.md](NOTES.md) is the long version, with every bug in one table.

## Check it

```bash
python tools/preflight.py email.html email-ampscript.html
```

The checker fails on:

- an HTML comment inside an Outlook-only block, unbalanced Outlook blocks, or the `[if !mso]` wrapper written without its inner space (see the editing notes);
- tables, rows, cells or other tags that are opened and not closed properly;
- AMPscript with unbalanced `%%[ ]%%`, `IF`/`ENDIF` or `FOR`/`NEXT`, three percent signs in a row, or personalization syntax inside an HTML comment;
- images without `alt`, `width` or `height`;
- tables without `role="presentation"`, links with an empty or `#` address, a missing `lang` or `<title>`;
- characters outside plain ASCII, or a charset declared too late;
- a message over Gmail's 102 KB clipping limit;
- a style block over 8,192 characters or with unbalanced braces (Gmail is reported to drop the whole block in both cases).

It warns when an image isn't an absolute `https` address. The tag checks cover the markup every app except classic Outlook reads, and the charset check only runs when the doctype is in the first 1,024 bytes, so it doesn't apply to `email-ampscript.html`, which starts with the AMPscript block.

```bash
python tools/ampscript_run.py
```

Runs the eleven AMPscript test cases. Each line says PASS or FAIL and what is wrong. It also stops on things Salesforce's AMPscript reference says Marketing Cloud rejects, such as a `FOR` loop counter declared with `VAR`.

```bash
python tools/ampscript_core_check.py ampscript-0.0.6.vsix
```

Runs the same cases through Salesforce Labs' AMPscript Core engine, as a second opinion that doesn't share my runner's assumptions. It needs the `.vsix` from [SalesforceLabs/ampscript-core](https://github.com/SalesforceLabs/ampscript-core/releases) and the .NET 8 and ASP.NET Core 8 runtimes. `AMPSCRIPT.md` explains the two changes its test copy needs.

```bash
python tools/send_test.py "tests/ampscript/demo/out/*.html" you@gmail.com
```

The sample covers one, two, three, seven and twelve properties, umlauts, a long name, a long property name, no name, no property data, and data only on the hotelier's row. The finished emails are already in `tests/ampscript/demo/out/` and open in any browser.

## Test it in Marketing Cloud

I couldn't do this step myself because I don't have an account. With one, it goes like this:

1. Run `python tools/ampscript_run.py --csv`. It writes the test cases as two CSV files in `tests/ampscript/`. Put your own address in the `EmailAddress` column of `RateConnect_Test_Sendable.csv`.
2. Create two data extensions with exactly these names. Every field is Text, except `EmailAddress`, which is the EmailAddress type.
   - `RateConnect_Test_Sendable`: sendable, with `SubscriberKey` as the primary key, related to Subscriber Key. Fields: `SubscriberKey`, `EmailAddress`, `hotelier_id`, `hotelier_name`, `property_name`, `commission_rate`.
   - `RateConnect_Properties`: not sendable. Fields: `hotelier_id`, `property_name`, `commission_rate`.
3. Import each CSV into its data extension.
4. In Content Builder, create an HTML email and paste in all of `email-ampscript.html`.
5. Open Preview and Test, choose `RateConnect_Test_Sendable` and step through the rows. Each row is one test case, and what it should show is in `tests/ampscript/cases.json` (`expect` and `forbid`).

The wrong-table case isn't in the CSVs. To test it, change `@propertiesDE` at the top of the script to a name that doesn't exist.

## Which file to send

- **`email.html`** works from any sending tool. The three placeholders show exactly as drawn in the design. In Marketing Cloud, `%%hotelier_name%%` and `%%property_name%%` are personalization strings, so the sendable data extension needs columns with exactly those names. Salesforce's documentation says a personalization string with no matching column makes the send fail, which is why the AMPscript version reads them with `AttributeValue()` instead.
- **`email-ampscript.html`** is for Marketing Cloud only; elsewhere the script shows as text. It needs the data extensions below. The lookup table, `RateConnect_Properties`, should exist even if it's empty, because the script looks it up by name. I couldn't test in Marketing Cloud what a missing table does. With an empty table, every hotelier falls back to the columns on the sendable row (that case is covered by the test runner).

## Data the AMPscript expects

These names are assumptions. The table name is set in the config block at the top of `email-ampscript.html`; the field names are in sections 1 and 2, right below it.

| Where | Field | Use |
| --- | --- | --- |
| Sendable data extension | `hotelier_id` | Key for the property lookup |
| | `hotelier_name` | Greeting. Empty gives "Hello," |
| | `property_name`, `commission_rate` | Fallback when the lookup returns nothing |
| `RateConnect_Properties` | `hotelier_id`, `property_name`, `commission_rate` | One row per property on Rate Connect |

All of these fields are Text, including `commission_rate`. A Number field in Marketing Cloud only takes whole numbers, so a rate like 10.5 would fail the import. A Decimal field would work, but I couldn't check whether it prints 12 or 12.00. Text prints exactly what is stored.

| Properties found | Intro | Tip 2 | "Add a property" banner |
| --- | --- | --- | --- |
| 1 | "Now that *Hotel X* is live" | "Current rate: 12%" | Shown |
| 2 or more | "Now that your *N* properties are live" | One line per property, five at most, then "+ N more" | Hidden |
| None, no fallback | "Now that your property is live" | Rate line left out | Shown |

## Editing notes

- The two HTML files share their markup. A change to one must be made in the other.
- Never put an HTML comment inside an `<!--[if mso]>` block. It ends the block early for every other client.
- To hide something from classic Outlook, write the wrapper with a space inside: `<!--[if !mso]><! -->` ... `<!-- <![endif]-->`. T-Online's webmail deletes everything inside the usual spelling without the space. The checker fails on it.
- In classic Outlook, "View your campaign" is a VML shape with a fixed width. Its text is live, so it can be translated, but if the label gets longer, raise the `width` on its `v:roundrect`.
- "Add a property" is live text everywhere. In classic Outlook it's a plain cell with square corners, on purpose, so it can be translated and stays readable in dark mode.
- The number circles are images (`images/circle-N.png`) except in classic Outlook, which draws them in VML. A new tip needs a new circle image and a new VML number.
- Dark mode: never put a recolored thing (background color, text) next to one that is never recolored (image, VML shape). `tests/RESULTS.md` explains why.
- Link targets are placeholders. The Figma file carries no URLs.
- The images are served from this repository: `https://raw.githubusercontent.com/PewPewzxc/case-study-trivago/main/images/`. If they move, change every address that starts with it in each HTML file: every `src` address and, in the header, the `background` attribute and `background-image`. `tools/send_test.py` refuses to send while any of them does not load. GitHub is only the host for this case study, so please keep the repository public and don't rename it. In a real send, the images would be uploaded to Marketing Cloud's Content Builder, which serves them from Salesforce's own image servers.
